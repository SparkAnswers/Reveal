Reveal — reveal-mode catalog

35%

Each card renders the same placeholder scene with one reveal mode at the current (eased) progress p. Progress is the elapsed fraction between the start date and the reveal date; this page assumes a 30-day window. Tags show the implementation technique and whether animated GIFs keep playing without re-encoding.

Design notes

Recommended default mode

Blur (blur). It is the most legible "getting closer" metaphor, it works on photos, text and GIFs alike, it degrades gracefully at any panel size, and it is a single CSS filter (no layout, no canvas, no per-frame work). Pixelate is the fun alternative but needs canvas and therefore loses GIF animation; Jigsaw is the best "calendar feel" for long windows.

Best modes for animated GIFs

Anything where the original <img> stays in the DOM and is only filtered, clipped or masked keeps GIF playback for free: Fade, Blur, Brightness, Color, Wipe, Iris, Scanlines, Scratch-off (SVG/CSS mask), and the tile modes (Jigsaw, Shuffle, Mosaic, Advent) because each tile is just background-image of the same URL with a background-position offset (the browser shares the decoded animation across tiles). Pixelate is the only canvas mode: for GIFs it would need frame decoding (ImageDecoder API / gifuct-js) or a fallback to Mosaic/Jigsaw. A cheap pixelate approximation that keeps GIFs is image-rendering: pixelated on a downscaled <img> wrapped in an upscaling transform; it is lower quality but worth offering as the GIF fallback.

Recommended easing default

ease-in (quadratic). Linear reveals too much too early for Blur/Pixelate (the image is recognisable at ~40%), which kills the suspense; ease-in keeps the image obscured for most of the window and then "rushes" to the finish. For calendar-style modes (Advent, Jigsaw) use steps(days) so a visible change happens exactly once per day and users have a reason to come back. Expose easing as a panel option with those two defaults per mode.

Mode enum proposal (panel options)

// panel option `mode`  (RevealMode)
'fade' | 'blur' | 'pixelate' | 'jigsaw' | 'shuffle' | 'wipe' | 'iris' |
'scratch' | 'blinds' | 'mosaic' | 'brightness' | 'color' | 'advent' |
'puzzle' | 'combo'

// related options
easing:    'linear' | 'ease-in' | 'ease-out' | 'steps'    // steps = one step per day
direction: 'ltr' | 'rtl' | 'ttb' | 'btt' | 'center'     // wipe / blinds / iris
grid:      { cols: number, rows: number }                 // jigsaw / shuffle / mosaic / puzzle
seed:      number                                          // tile order; default = hash(reveal date)
combo:     RevealMode[]                                    // stack of modes, applied in order
intensity: number                                          // max blur px / max block px / etc.

Other notes

  • Seed every random order from the reveal date (or a user-provided seed) so the panel looks identical on every dashboard refresh and for every viewer.
  • All modes are written as render(container, p) and are idempotent: they build DOM once and update on subsequent calls, so a Grafana panel can call them on every data refresh without flicker.
  • Rendering is resolution-independent except Pixelate/Puzzle which use the stage size in px; the plugin should read the panel size and re-render on resize.
  • Combo is just function composition; the engine should allow an ordered array of modes with each mode receiving the same p (or a per-mode remapped p range).
